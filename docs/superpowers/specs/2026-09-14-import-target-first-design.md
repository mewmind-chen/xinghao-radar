# 智能导入：类型优先设计

## 目标

智能导入只完成一件事：用户先明确要导入什么，再把来源交给系统，系统按该业务类型提取并生成可人工确认的预览。

固定流程：

1. 选择导入类型。
2. 粘贴文本、选择文件、拍照或粘贴图片。
3. 按已选类型识别。
4. 在精简预览中核对、修改、选择记录。
5. 确认写入并得到真实结果。

## 核心规则

- 类型是识别前的硬约束，不是识别后的展示筛选。
- 页面不得先做“中性识别”，再把同一批旧结果转换为其他类型。
- 模型返回的业务类型不得覆盖用户选择；服务端必须再次强制校验目标类型。
- 更换类型必须使旧预览失效，并用原始来源重新识别；禁止复用旧字段冒充新结果。
- 普通页面不提供“混合/逐行选择类型”。历史接口如需兼容可保留，但前端不得调用。
- AI 只负责提取候选数据，不决定写入目标；所有记录仍须人工预览确认。
- 新识别结果默认不勾选。“待确认”表示需要人确认，不等于必须修改。

## 各类型只展示和写入相关字段

- 客户询价：型号、品牌、客户、询价数量、TP（接受价）、币种。
- 渠道推货：型号、品牌、渠道、数量、DC、报价及币种、交期（来源具备时）。
- 库存入库：型号、品牌、数量、DC、仓库、供应商、成本及币种。
- 在途：型号、品牌、数量、DC、供应商或来源、预计到货信息（来源具备时）。
- 潜力型号：型号、品牌，归当前导入用户自己的关注池。

其他来源信息可以保留在折叠的原始证据中，但不得混入无关业务字段，更不得写入错误的数据表。

## 页面结构

- 页面主体只保留三个连续区域：类型、来源、预览。
- 删除“中性识别”“识别后选择类型”等说明与步骤。
- 删除重复的提示条、同义状态、长篇功能介绍和大段校验说明。
- 正常状态只显示一行摘要，例如“共 7 条 · 可确认 4 · 需修改 3”。
- 原始证据、详细错误和低频字段默认折叠；用户需要时再展开。
- 预览列随类型变化，不显示无关空列。
- 主操作保持唯一且清晰：识别预览、确认写入；更换类型属于重新开始。
- 所有按钮必须完成真实动作，具备处理中、防重复、成功、失败和刷新闭环。

## 数据与异常边界

- 同一个客户询价文件可包含多个客户；按每行客户导入，老客户精确匹配，新客户直接创建。
- 型号原字符不能由 AI 擅自改写；多候选型号必须人工选定。
- 批量写入必须防重复和半成功，失败不能展示整批成功。
- 已有型号主档不重复创建，只新增对应的业务事件。
- 类型错误、字段缺失、网络失败和识别降级必须明确区分，不能用空白页面代替。

## 验收标准

1. 所有来源入口都必须携带用户已选类型，前端不再发送 `neutral`。
2. 选择“客户询价”后，预览与写入均不出现库存、仓库、供应商、成本等字段。
3. 模型即使返回其他类型，最终候选仍受用户目标类型约束。
4. 更换类型后旧预览不可继续选择或写入，必须重新识别。
5. 预览状态、勾选数和确认按钮数量始终一致；待确认但无需修改的记录可以直接勾选。
6. 电脑、390×844、360×800 均无横向溢出、文字竖排、遮挡和失效操作。
7. 覆盖文本、文件、图片、拍照、相册和粘贴图片入口，以及成功、失败、重复提交和类型切换。
